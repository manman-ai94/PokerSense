# 信号灯窗口（2026-10-07 定稿）

打开本地服务的首页（`/`）就是这个窗口；旧观察页（本桌设置、详细数据、复查）在 `/classic`，
窗口右上角“设置和数据”进去。主人定的三条规则：

1. 关键信息必须醒目：该怎么打用整块颜色和最大的字，一眼看到。
2. 不能平庸。
3. 每个面板、每个功能都必须实时，并且真能用：只显示 `/api/status` 里实时送来的数据，
   缺什么就明确说缺什么，不放假数据、不猜。

## 颜色就是动作

| 颜色 | 意思 |
|---|---|
| 绿 | 跟注 / 过牌 |
| 橙 | 下注 / 加注 |
| 红橙 | 全下 |
| 蓝 | 弃牌 |
| 深灰 | 还没轮到你、看不到牌桌、还没开始 |
| 灰蓝 | 这一步不给建议（单挑翻牌、规则不支持、多人底池没推算出对手的牌），下面的数照样实时 |
| 灰色斜纹（会动） | 正在算 |
| 黄黑斜纹边框 | 识别不全、画面断了（超过 3 秒没有新画面） |
| 黄 | 你刚做完一步：这一步的打分，下次轮到你之前一直显示 |

## 每个状态从哪来

- 建议：`solver_advice_v1`。翻前是 `aa_preflop` 算出的每个选择值多少大盲（`options`）；
  单挑转牌、河牌是求解器的混合打法（`advice` 的频率）。下注额达到你的筹码就写成“全下”。
  牌桌左上角的蘑菇池（`mushroom_pool_v1`）满 4 人时交给翻前算法；你当小盲时算进底池，依据写“算上蘑菇池 N：你是小盲，赢下底池就一起拿走”（`mushroom_pool`）。
  翻牌后几个人的底池（`kind: "multiway"`）没有求解器，按你对他们的牌能赢几成和价格定一个动作，和记分牌上的
  `range_multiway` 同一条规则（`multiway_bot.choose`）：没人下注时超过 4 成就下注约 2/3 池，否则过牌；
  面对下注超过 6 成就加注到约一池，够价格（`cuts.call` = 跟注额 ÷ 跟完的底池）就跟，不够就弃。
  理由写成“你能赢 31%，跟注只要 25% 就够”；依据写明“没有多人求解器”。你的筹码没读到时只给数字。
- 价格行、三个数（要赢多少才不亏、能赢多少、有效筹码）：`hero_controls_v1`、`table_math_v1`。
  有了对手范围胜率（`range_equity`）就换成“你对他的范围能赢”。翻牌和几个人的底池没有求解器，后台按每个对手的动作用同一个真人打法模型推算他们可能拿的牌（`scoreboard/ranges.py`，约 0.1–2 秒），算好就换成“你对他的范围能赢”或“你对他们的牌能赢”（几个人的底池这时同时给出建议，之前显示“正在算”）；没算出来（行动记录或公共牌没读全）仍是对随机牌的胜率，并写明只当上限参考。
- 右边牌桌、这一手：`seat_states_v1`、`stacks`、`action_history_v1`；位置名按庄位和发了牌的座位顺时针排。
- 计时：“已等 N 秒”从你的按钮出现时开始算，同一街你每动一次重新算；“已算 N 秒”从开始算时起。
- 打分和本场记录：`grade_v1`（`aa_grading.AAGrades`）。轮到你时的建议（求解器在你点完以后才算完的也算）
  和当时的牌面先记下，等这一手的行动记录里出现你这一步再打分：翻前看比最好的选择少赢几个大盲
  （不到 0.05 最佳、0.5 以内可以、2 以内小失误，更多是错误）；转牌、河牌看求解器多常这样打，
  各种下注额合在一起算（最常用或一半以上最佳、两成以上可以、2% 以上小失误，更少是错误）；
  几个人的底池和建议一样是最佳，不一样时看你能赢的离你那样打的线差多远（5 个点以内可以、15 个点以内小失误，更远是错误）。
  对不上任何选项的动作（面对下注却读成过牌等）不打分，不猜。换一个画面来源就重新记一场。
- “行动后再看”开关（右上角，浏览器记住）：轮到你时先不显示建议，写“你先决定”，你点完再打分。
- 刚轮到你的 1.5 秒内没读全（牌在滑入、换街）先显示“稍等”，过了才报“识别不全”；
  看不到牌桌 8 秒内当作两手牌之间的动画，不报警。

画面怎么算出来在 `ui/aa-live/signal_view.js`（纯函数，测试 `tests/ui/test_signal_view.js` 覆盖每个状态），
`signal.js` 只负责每 250 毫秒取一次状态并画出来，所有读到的文字都用 `textContent` 写入。
窗口宽度不到 560 像素时只留颜色区；左右并排时整页不滚动，右边一栏自己滚。

## 全下以后

下注结束、有人全下（最多一个人筹码更多没全下）、牌还没发完，并且你还在这一手里：整块写“保险别买”。AA 这时会让领先的人买转牌或河牌的保险，牌桌给的赔率每一档都比公平赔率低，买了通常亏掉保费的 2 到 5 成（`aa_insurance.py`）；底池超过 3 个人不能买，就只写“全下了，等发牌”。不靠认出保险弹窗，只看座位状态和公共牌张数；发牌和摊牌时公共牌会闪，同样的座位读到过 5 张公共牌后就不再显示。这一步的打分在发完牌后显示，也一直在本场记录里。

## 置顶小窗

右上角“置顶小窗”用 Chrome 的画中画窗口（Document Picture-in-Picture，Chrome/Edge 116 以后，只在本机地址可用；
Safari 没有，点了会提示改用 Chrome）：颜色区整块搬进一个浮在所有窗口上面的小窗（约 380×600，可以拖大小），
只留你的牌、建议、混合比例或各选择的值、两个数；打分时两个数换成本场照着打几步、翻前少赢多少。
大窗口原地写“建议在置顶小窗里”。点小窗的“回到大窗口”、大窗口的“收回到这里”或直接关小窗，颜色区搬回来。
小窗开着时，大窗口被挡住或缩小也照常取数据（用小窗自己的计时器，后台标签页的计时器会被浏览器放慢）。

在 Mac 上，启动脚本装了 Chrome 就用 Chrome 打开窗口（`packaging/aa_live_entry.py` 的 `open_page`），没装才用默认浏览器。

## 录像

接采集卡观察时，顶上多一个“录像”按钮（`POST /api/recording {"on": true|false}`，只有画面来源是采集卡时才接受）。
本机服务本来就占着采集卡，所以直接把它已经拿到的画面写下来（`aa_recorder.py`），不用另开录像程序：
存到数据目录的 `PokerSense_private/aa-mac-recordings/<日期-时间>-live/`，和 `record-aa-capture.command` 同一种格式
（固定 30 帧、每 60 秒一段 H.264，带 `segments.csv` 和 `recording.json`）；服务只留手机那一条画面，
写的时候放回黑底 1920×1080 原来的位置，所以回放和测量工具照常裁切。编码在单独的线程，忙不过来时跳过新画面、重复上一帧，不拖慢识别。
录制中按钮变红、显示“录制中 分:秒 · 停止”，再点一下停止；点“停止”观察、关页面 3 分钟后或录满 2 小时也会自动停，
停下后写“已存好 · N 分钟”（鼠标放上去显示文件夹）。窗口太窄时按钮收起，录制中仍然显示，方便停止。

软件只显示建议，不替你点、不下注、不控制扑克客户端。
